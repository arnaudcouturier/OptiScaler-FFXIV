**Preview Neural Rendering.** `[FFXIV] PreviewNR` (false) runs the DLSS NR model on each open character preview window. The NR model only runs on Direct3D 12, so the preview image is handed to the DirectX 11 on 12 bridge's device through shared textures and fences, processed there and drawn from a shared result texture; every failure keeps the native image and switches preview NR off for the session. It needs an NVIDIA card, the bridge running, `nvngx_dlssnr.dll` and `nvngx.dll_dlssnr.dll`; `[DlssNr] Enabled` is not needed, the `[DlssNr]` tuning is shared. It works alone or with `PreviewDLSS`. Alone it runs on the native preview image (bring-up: native size, synthetic guides: a cleared depth and zero motion). With both on it runs on the Super Resolution result (production: the 2x output, copied into shared images, with copies of the preview's own depth and motion at the render size, the Super Resolution feature's depth convention and motion scale), between the Super Resolution evaluate and the alpha pass; the original alpha is recomposed onto the NR image exactly as it is onto the plain Super Resolution output, and any render where NR cannot run (the model is still being built, no command list free, a failure) shows the plain Super Resolution image. With both options on (and `PreviewNRBeforeSR` off), only the production model is built (at twice the size): a render that Super Resolution did not evaluate (the first renders after a window opens, a rejected finisher) shows the native image, exactly as with `PreviewDLSS` alone, and the first renders after the model is built are plain Super Resolution; preview NR on the native image (bring-up) runs only for a preview Super Resolution does not serve (`PreviewDLSS` off, Super Resolution latched, a failed or too large preview); the cost per window is one NR pass at 2.2 megapixels. `PreviewNRLate` applies to the bring-up only (the alpha recomposition needs the colour of the same render). It takes the equipment preview before the spatial AA; for a draw it has no result for (the first renders after a window opens, renders it skipped, a finisher the checks reject) the spatial AA still takes the draw when `PreviewAA` is on, so the AA is not lost, unless `PreviewDLSS` is on and its pass runs (then the draw stays as it is; while the `PreviewDLSS` pass cannot run, the AA takes it). `PreviewNRLingerSeconds` (5) keeps a window's model after the window closed; `PreviewNRLate` (false) shows the previous frame's result and avoids the GPU wait on the DirectX 11 side at the cost of one frame of lag. Cost per open window (GPU time, video memory) is shown in the menu and the log (`CharaView NR:` lines); it has not been measured in game yet. By default the placement is after Super Resolution when both options are on; NR before Super Resolution (a pre-pass on the render-size image) is the experimental `PreviewNRBeforeSR` option described below. In game still to be checked: the D3D12 state tracking of the production inputs under the debug layer, whether the model accepts guides smaller than the colour as the main pass's do, the image quality on the alpha-masked silhouette and on moving characters, and the cost with several windows open.

**NR before DLSS (experimental).** `[FFXIV] PreviewNRBeforeSR` (false) runs the preview NR on the render-size picture before the DLSS evaluate instead of on the DLSS result: the slot's colour, depth and motion go through the NR model at the render size and the result is the evaluate's `Color`. The model works at a quarter of the pixels, so each open window is expected to use less GPU time and video memory than NR after DLSS (not measured yet: the cost lines in the log will show it); the trade-off is that NR sees a jittered picture that has not been anti-aliased, so shimmer or trails on hair and cloth are possible (the default stays after DLSS). It has an effect only with `PreviewDLSS` and `PreviewNR` both on; `PreviewNRLate` does not apply to it (the result is always used in the same frame). Fail-open: a render for which the NR step has no image yet (the model is being built, no list free, NR failed) is evaluated on the plain picture and does not start the NR after DLSS; if the DLSS evaluate refuses the NR image, that render is evaluated again on the plain picture, NR before DLSS is switched off for the rest of the session with one log line and NR runs after DLSS as before. The same switch-off happens when the repeat on the plain picture fails too: the preview then falls back to the game's own picture for about ten seconds, but a problem of the NR image cannot end the Super Resolution path. The Super Resolution history is reset when the picture handed to DLSS changes between the plain and the NR image and for the repeat after a refusal, so the two pictures are not blended. The reset for a change of the picture is given at most once per half second for a window: if the NR step is skipped on every other render (for example under heavy GPU load with several windows open) the picture alternates, and a reset on every change would keep DLSS from ever accumulating. The menu line "NR before DLSS" and the log show how many of these resets were given. A failure inside the NR step itself (for example an input that does not fit the stream) switches off all preview NR for the session, as it does for NR after DLSS; that is intended, because those failures do not depend on the placement. With `PreviewDebugTint` the preview is cyan when the evaluate used the NR image. Switching the key rebuilds the window's model after half a second. Whether the driver accepts the shared NR image as the evaluate's input, and the picture quality, are checked in the game (a refusal falls back as described); the cost lines in the log are labelled "pre-SR".

**Probe output.** While PreviewProbe is on, the button "Save preview images" (or the command `dump`) writes `native.png`, `aa.png`, `dlss.png`, `nr.png` (whichever exist; `nr.png` is the NR result converted to 8 bits), each with `alpha-<name>.png` (the alpha channel as a grayscale picture), and `state.txt` (one `key: value` per line) into a new `OptiScaler\PreviewDebug\<yyyyMMdd-HHmmss>\` folder; at most 40 files and 300 MiB per session. About twice a second the probe reads `OptiScaler\chara-probe.cmd` (one command per line: `tint|flood|aa|dlss|upscale|copies on|off`, `dump`, `state`, `reset`, `help`; at most 4 KiB), runs it, deletes it and appends the results to `OptiScaler\chara-probe.out` (capped at 256 KiB). Commands change the settings in memory only; the ini file is not touched.

**Safety.** It fails open: any doubt leaves the native image. It reads the game's `.text` once, read-only, for an 18-byte code pattern that must match exactly once at the documented addresses; otherwise the feature switches itself off for the session with one log line. The DLSS pass uses the driver's real D3D11 NGX and latches off for the session if feature creation fails. Switching `PreviewDLSS` off at run time releases the preview GPU objects (images and NGX features) as soon as their last GPU work has finished.
