# HUD-less frame generation: status and session measurements

Material moved out of [FEATURES.md](../FEATURES.md#hud-less-frame-generation) on 2026-10-23; the paragraphs are copied unchanged; internal names are renamed or removed.

**Status.** Opt-in, off by default. Tested in SDR with DLSS-G 2x to 4x on an RTX 4090; no visible gain was reported. **Recommendation: use `recomposition`; treat `ui_free` as experimental.** In one session on 2026-10-22 (SDR, RTX 4090, DLSS-G 2x) `ui_free` stayed in `Fallback(MaskCoverage)` for most presents: the detected UI mask covered 50 to 100 % of the picture (as few as 0 of 600 presents captured), so the UI-free path did nothing useful, NVIDIA's own UI recomposition is switched off in that mode, and DLSS-G interpolated the whole frame, UI included. The author saw a faint, fast micro-stutter in motion, only with frame generation on, and it was gone with `Mode = recomposition` (engine Active with 554 to 600 of every 600 presents captured and 0 to 2 fallbacks in the log; dynamic multi-frame generation then reached about 3x). The cause of the mask failure in that scene is not investigated. Earlier sessions (see HUDLESS.md section 15a) saw `ui_free` Active on 96 to 100 % of presents, so the outcome depends on the scene. HDR output with `ui_free` is untested. One GPU hang happened at the experimental 6x unlock after the mode was toggled quickly. Design, measurements and limits: [HUDLESS.md](../HUDLESS.md).
