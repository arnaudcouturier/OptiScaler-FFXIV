# NR model version picker and NR pause on focus loss: full description

Material moved out of [FEATURES.md](../FEATURES.md#nr-model-version-picker) on 2026-10-23; the paragraphs are copied unchanged; internal names are renamed or removed.

**Pause on focus loss.** `[DlssNr] DisableOnFocusLoss` (off by default, experimental) pauses NR while the game window is not focused. It covers the D3D12 and D3D11-bridge scene NR and the character preview NR; native Vulkan is not paused. The preview shows its plain image while paused and resumes with a clean history; its paused renders are not counted as fallbacks in the preview card (the card lines say "focus pauses not counted"; the dump keys `nr.fallbacks` and `nr.production.fallbacks` keep their names and also leave focus pauses out), and the log shows `CharaView NR: paused, window not focused` and `CharaView NR: resumed`. `PauseOnFocusLoss` is accepted as another name for `DisableOnFocusLoss` (a copied ini from another build keeps working): it is moved into `DisableOnFocusLoss` when the ini is read and saved back as `auto`; when both are set, `DisableOnFocusLoss` wins. Pausing starts after 1 s without focus (at once when minimised), a little later than SirenBrink's v6.0, which pauses at once. Status: new; unit-tested, nothing of the preview pause has run in game (the in-game proof needs a visible but unfocused window, not a minimised one).

**Model version picker (live).** Put each NR model file in its own folder named `OptiScaler\NR.<version>` (digits separated by dots, for example `OptiScaler\NR.310.9\nvngx_dlssnr.dll`) next to the game, beside or instead of the old single `nvngx_dlssnr.dll`. The `NR model version` combo in the Neural Rendering card lists the old file ("Legacy location") and every valid folder with its file version, size and the start of its SHA-256 (computed in the background), and switches the running model without a restart, in the scene and in the character previews. `Automatic` (the default) is the newest version; on a tie the old file wins, and a folder that appears later never moves Automatic by itself (the card's `Rescan` button looks again). A choice that is not installed never falls back to another model: the card says Neural Rendering is unavailable and the pass shows the plain upscaler image until a model is chosen again. Clicks are coalesced (a switch happens 250 ms after the last click). A switch parks the model's features behind their GPU fences, clears the NR history and the bottleneck-reuse state (reuse stays off on the new module until its kernel blob is verified), forgets a failure that the old model caused (a failure of the forwarder, the NGX core, the colour codec or the depth and motion inputs is kept), and loads the new file by its full path; model files are never unloaded, so every model used in a session stays in memory. The old recursive search for `nvngx_dlssnr.dll` skips every folder whose name starts with `NR.`, so a versioned folder is never picked by search order. A failed or partial rescan keeps the previous list and the card says so. Restart is needed only where it physically is: the NGX core's first search path (set once at startup), native Vulkan NR, the hybrid FP4 precision (`Precision=4`) and the AMD bridge; the card says so from the real state. The hybrid FP4 lock is sticky: once `Precision=4` was in use in a session, live switching stays off until the next start, because its prepared weights belong to the device and not to the model file. Config: `[DlssNr] Runtime` (empty or `auto` = newest, `legacy`, or a folder name such as `NR.310.8`); it is not part of the saved NR presets. Log: `DLSS-NR runtime catalog: N candidate(s)`, `DLSS-NR runtime revision N: <id> (<path>), file version ...`, `DLSS-NR runtime generation change`, `NR reuse: runtime switched ...`, `CharaView NR: NR runtime revision N ...`; the SHA-256 of the loaded model is logged only after the card has been opened once (hashing starts then, not at startup, so the default path reads no extra file). Status: new. The catalog, scan, selection, switch, text and glue are unit-tested (including a test that two same-named DLLs in two folders load as two modules when loaded by full path); nothing of it has run in game. Known limits: the first load of a second 276 MB model happens on the render thread and will probably be a hitch; whether NVIDIA's code looks itself up by file name (which would see the first copy loaded) cannot be seen without running two models in game, so the first in-game check compares the two versions' own version lines; the combo shows the request while the status line shows the model actually loaded (they can differ when a create failed or switching is locked, the status line is the truth); a preview stream is rebuilt lazily after a switch; the capability block is bound again to each model by the forwarder's own populate step, which could only be tested with stand-ins. Code: `OptiScaler/ext/nr/runtime/` (`NrRuntimeCatalog.h`, `NrRuntimeScan.h`, `NrRuntimeSelection.h`, `NrRuntimeSwitch.h`, `NrRuntimeCore.h`, `NrRuntime.cpp`, `NrRuntimeText.h`), `ext/nr/pass/DlssNr_Dx12.cpp` (`RuntimeHost`, `PollRuntime`), `ext/ffxiv/chara/CharaNr.cpp` (`SyncRuntime`, `NrPreviewRuntime.h`). Seams: nr `AppendNgxSearchPaths` (body changed, no new seam). Menu: `dlss_nr` card, combo `NR model version` and `Rescan`.
