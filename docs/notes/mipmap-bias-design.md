# Automatic mipmap bias: design and both modes in full

Material moved out of [FEATURES.md](../FEATURES.md#automatic-mipmap-bias) on 2026-10-23; the paragraphs are copied from it with only internal names renamed or removed and the in-game status corrections of 2026-10-23. In the create-time paragraph the card position is corrected to "after Anisotropic Filtering", as in the layout table.

**Two modes.** In FFXIV the bias is applied when the game binds a sampler (the bind-time mode, below). In other games, or if the sampler hooks cannot be attached, the older create-time mode is used (the paragraphs after the bind-time ones). The older mode stands down while the bind-time hooks are attached.

**Bind-time mode (FFXIV, on by default).** Keeps the texture sharpening matched to the upscaling ratio with no number to work out by hand and no restart after a quality change. The target is `log2(render width / output width)` of each DX11 upscaler evaluate (the render width is the smaller of the render subrect and the NGX Width, the output width is OutWidth, else the width of the Output texture, else the display width of the create), so native resolution (DLAA) gives 0, Quality 1.5x gives -0.585 and Performance 2x gives -1.0; `MipmapBiasAutoOffset` (-3 to 3) is added. The target is steadied: a change smaller than 1/64 of a log2 step is ignored, at most 4 new targets per second are taken, and an evaluate whose output size differs by more than 10 % from the main one (a second feature, a preview window) is ignored until it has been alone for 2 s or 120 evaluates.

**How it is applied.** FFXIV caches its sampler states, so a bias written when a sampler is created never reaches the samplers made before a quality change. The fork therefore applies the bias when a sampler is bound: it hooks `SetSamplers` and `GetSamplers` of the six shader stages on the game's immediate context and, for the samplers the game made with a negative bias (mipmapped, not comparison/minimum/maximum filters), binds an immutable copy that carries the current target. `GetSamplers` still returns the game's own sampler, so state saves and restores see what the game set. Samplers are recognised when the game creates them (an own hook on `CreateSamplerState`, attached at the first upscaler create and detached first, because two Detours hooks on one function must be undone in reverse order) or, for samplers made earlier, at their first bind. At most 256 samplers take part; the rest keep the game's bias. The copies are made at the evaluate, not on the bind path: when the target changes the samplers bound at that moment are rebound at once, and a sampler whose copy is not ready yet is bound as the game made it for at most one evaluate. There is no lock on the bind path. Deferred contexts and any other context are passed through untouched, and any failure leaves the game's own samplers. The hooks follow the immediate context recorded when the device was hooked; if the evaluate arrives on another context of the same class (a ReShade proxy), the hooks move to it and a warning names both contexts.

**Add or replace.** Some games add their own DLSS bias (FFXIV appears to add `-1 + log2(scale)` to one family of samplers), others keep constant art biases. Until the game's biases are understood, the target is ADDED to the game's own bias, which is what the manual setting does. The fork watches the samplers the game makes and the target in force when each was made. A new bias of the same sampler family that differs from an older one by the same amount as the target moved (the target must have moved by at least 0.25, the match is within 0.08) means the game follows the mode: the mode becomes REPLACE, provisional at first and confirmed when a further quality change gives another such pair or a second sampler family shows one. Several pairs that disagree keep ADD and the fork looks again at the next change; ADD for lack of data is never final. REPLACE applies only the change of the ratio since a sampler was made, plus the offset, so the game's own constant part is kept: at native resolution the game's biases are untouched, and a sampler made at Quality with -1.585 stays -1.585 until the ratio changes. A session that stays on Quality never reaches "confirmed" and stays provisional REPLACE (the look is the right one). The decision is logged (`Bind-time mip bias: ... REPLACE mode ...` or `... staying in ADD mode ...`).

**Settings.** `[Mipmap] MipmapBiasAuto` (default on for FFXIV, off for other games; `AutomaticFFXIV` is accepted as another name, the main key wins), `MipmapBiasAutoOffset`, `MipmapBiasObserve` (debug, off: logs every distinct original sampler bias seen at each ratio). A value set by hand (`MipmapBiasOverride`, also the "Mipmap Bias" card) always wins: the bind-time mode applies nothing while it is set and the log says `Bind-time mip bias: not applied because MipmapBiasOverride is set by hand`; clear it (set it to `auto`) and the feature resumes at the next evaluate without a restart. A live ini that carries a number in `MipmapBiasOverride` therefore gets none of this until that key is set to `auto`.

**Status.** Bind-time mode: ran in game (RTX 4090) on 2026-10-20, 21 and 23; no fps loss measured (comparison across sessions, not a same-session A/B); look not compared. The pure rules, the sampler table, the bind path, the six stages through real Detours hooks on a software D3D11 device, the settings and the install order are tested offline (`tests/ext/upscaler/mip_bind_*`). The older create-time mode ran in sessions with the manual value.

**Known limits.** The detector can mistake two art values of one sampler family that lie exactly one target move apart for a tracking pair; REPLACE is one global mode, so art samplers made at different ratios may differ in look (an in-game A/B is needed before treating families separately); command-list playback (deferred contexts) binds samplers without passing the hooks until the next rebind, and FFXIV uses the immediate context; the table never recycles dead entries (a warning is logged when 256 are used); the evaluate sizes (`Width` or subrect, `OutWidth`) are read as FFXIV reports them and not yet seen live; the context handling rests on the hooked class's function being the same and was tested with fake pointers and two software devices, not with a real ReShade wrapper; the hooks are attached or detached with the calling thread only, so a thread inside the first bytes of a patched function at that moment is a risk accepted at quiet moments.

**How to check.** Remove or set to `auto` any `MipmapBiasOverride` in the ini. Start the game with default settings and read `OptiScaler.log`: `Bind-time mip bias: sampler hooks installed ...`, `CreateSamplerState hook installed` at the first upscaler create, then one `Bind-time mip bias: render width W, output width O, ratio bias B, offset X -> target T (add mode, first measurement)` line and one line per later change of the quality preset (with the default offset of 0 the targets are 0.0000 at DLAA, -0.5850 at Quality 1.5x, -1.0000 at Performance 2x). After the first change one decision line says whether the game's own sampler biases follow the mode (`REPLACE`) or are art values (`ADD`). The textures must keep their sharpness after each change without a restart and the frame time must not change. With `MipmapBiasAuto=false` there are no `Bind-time` lines.

**Code:** `ext/upscaler/MipBind.h` (target, eligibility, add/replace detector, gate, texts), `ext/upscaler/MipBindEngine.h` (sampler table, variants, bind path), `ext/upscaler/MipBindControl.h` (controller and install plan), `ext/upscaler/MipBindHooks.cpp` (attaches it to the game). **Seams:** no new seam; `OnD3D11DeviceHooked`, `OnD3D11Unhook` and `OnUpscaleBoundary` also reach the bind-time module, and the first upscaler create reaches it through `mipbias::OnFeatureCreate`. **Config:** `[Mipmap] MipmapBiasAuto`, `AutomaticFFXIV`, `MipmapBiasAutoOffset`, `MipmapBiasObserve`, fragment `ext/ini/Mipmap.ini`. **Menu:** card "Automatic Mipmap Bias" in the Textures tab.

**Create-time mode (other games, or when the hooks cannot be attached).** The paragraphs below describe this older mode.

**What it does.** Works out the texture sharpening (mipmap bias) that goes with the upscaling ratio, so there is no number to calculate by hand. While `MipmapBiasAuto` is on, the value is `log2(render width / display width)` of the newest upscaler the game created (the same number as the calculator in the "Mipmap Bias" card, with the output scaling multiplier taken into account), plus an optional offset. It is applied the way upstream already applies `MipmapBiasOverride` to the samplers the game creates: added to the game's own bias, only for samplers that already have a negative bias unless "MB Override All Textures" is ticked, and, with the upstream "MB Fixed Override" option, replacing those biases by the single value (the Scale option is not supported, see "Modes and limits" below). It follows the latest accepted create, so 3840x2160 (native DLAA at the login screen) gives 0, a forced Quality preset (2560x1440) gives -0.585 and Balanced (2258x1270) gives -0.766. A create that is not a game scene (a size missing or outside 20 to 16384, a display narrower than 640 pixels, a portrait display such as the character preview's) is ignored and leaves the value alone. The override stays engaged for as long as the option is on; turning it off puts your own `MipmapBiasOverride` from the ini back. Like the manual value it only reaches samplers created after a change: samplers the game made earlier keep theirs.

**Status.** Create-time mode: opt-in, off by default; ran in game on 2026-10-19; the bind-time mode replaced it as the default. The sampler path is the manual value's, which runs in every tested session; the automatic part (which create to follow) was also replayed offline on the logged sessions.

**Code:** `ext/upscaler/MipBias.h` (formula, source policy, log and menu texts, tested in `tests/ext/upscaler/mip_bias_*`), `ext/upscaler/MipBias.cpp` (glue), `ext/upscaler/menu/MipBiasMenu.cpp`. **Seams:** none added; the existing upscaler seam `ApplyForcedQuality` also hands every feature create to the automatic mip bias. **Config:** `[Mipmap] MipmapBiasAuto`, `[Mipmap] MipmapBiasAutoOffset` (-3 to 3, default 0), fragment `ext/ini/Mipmap.ini`. **Menu:** card "Automatic Mipmap Bias" in the Textures tab, after Anisotropic Filtering.

**Good to know.** A manual number worked out for another preset gives a different look: forcing Quality with Balanced's -0.766 typed by hand becomes -0.585 automatically, and an offset of -0.18 gives back -0.765. FFXIV seems to add a bias of its own to one family of samplers, which stacks with this exactly as it does with a manual value. The sizes are read when the game creates its upscaler, so a game that changes its render size every frame without recreating it (dynamic resolution) is not followed; FFXIV recreates its upscaler on a quality change. With FSR 3.1 inputs the display size can still be changed after the automatic bias has read it (the upscaler takes it from its own structure), so the value there follows the size the game gave NGX; not relevant for FFXIV. In the menu, "Set" and "Reset" in the upstream card above are overwritten at the next quality change while this is on.

**Modes and limits.** The additive mode (the default) is the one this feature is made for. "MB Fixed Override" replaces the game's own per-sampler biases (for example -0.5, -1, -2) by the single value, which is a different look from adding to them. "MB Scale Override" multiplies the game's bias by the value; the automatic value is negative below 1:1, so the product would blur the textures (and at native DLAA a value of 0 would wipe out the game's own bias). So the automatic bias does not engage while Scale is on: the log shows one warning, `Automatic mipmap bias: not applied while MB Scale Override is on ...`, the card shows a red line, and your own manual value stays in force. Ticking or unticking Scale while the option is on takes effect at once while the Automatic Mipmap Bias card is on screen, and otherwise at the next quality change (the next time the upscaler feature is created; only the card looks in between, so with just upstream's Mipmap Bias card pinned to the Custom Tab, or another tab open, the multiplied value stays in force until then; with no manual value of your own, the override is then empty and the upstream card greys both mode checkboxes out; press "Set" in the card above to enable "MB Scale Override" again before unticking it), and the sizes of the creates seen in the meantime are kept, so unticking applies the right ratio immediately. The output scaling multiplier is counted only where the upscaler really enlarges its output, the condition the upscalers themselves use: output scaling on and (low-resolution motion vectors or render size equal to display size); with full-resolution motion vectors and a render size below the display size the log line shows no output scaling and the plain ratio is used. The extra offset slider limits a value typed with Ctrl+click to -3 to 3. Known limits: turning the option off from the menu gives your ini value back in two steps that the texture hook does not lock against (upstream's own "Reset" button has the same exposure), so turn it off while no level is loading, or edit the ini; a screen turned to portrait (display taller than wide) is not followed, because such creates are ignored, so on a rotated monitor the bias stays at 0 plus the offset.

**How to check.** Set `MipmapBiasAuto = true`, start the game and read `OptiScaler.log`: every accepted create logs a line (on FFXIV the two DLSS layers each read the same numbers, so every line comes twice in a row and the second one says `unchanged`; the existing `SetInitParameters Render Resolution` line is doubled the same way), `Automatic mipmap bias: create render 3840x2160, display 3840x2160, ratio 1.000 -> bias 0.0000 ...` at the login screen and `... create render 2560x1440, display 3840x2160, ratio 1.500 -> bias -0.5850 (was 0.0000 ...)` after the quality switch, and a create that was ignored logs `ignored create ...` with the reason. With `MipmapBiasScaleOverride = true` the first create logs the warning above instead and no `create render ...` lines. With the debug log level the existing `Overriding mipmap bias X -> Y` lines after it show the sampler hook received the value.
